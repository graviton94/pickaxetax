# 현상조사 (Phenomenon survey)

연구 순서는 배경 → 현상조사 → 목표 수립 → 중간 채우기다. 이 폴더는 현상조사 단계의 기록이다. 판정기나 하한 같은 해석 도구를 쓰지 않고, **제공사가 기록한 사용량**과 **세션의 성격**을 있는 그대로 잰다.

## 조사 대상
- **user01**: 프로젝트 대표 본인, 한 사람의 Claude 사용 전체. 표본은 한 명이므로 결과는 "한 사용자의 사용 방식"을 기술할 뿐, 일반화하지 않는다.

## 층

| 층 | 무엇을 | 원천 | 정밀도 | 상태 |
|---|---|---|---|---|
| 1. 세션 총량과 성격 | 세션별 입력(캐시 읽기·쓰기·비캐시)·출력·비용, 작업 종류, 기간, 모델, 접속 기기, 저장소·산출물 수 | Claude Code 클라우드 세션 기록의 usage 필드 | 실측 | ✅ `user01/cloud-sessions.json` |
| 2. 세션 내부 행동 | 사용자 지시 수, 호출 수, 도구 사용 분포, 압축, 컨텍스트 증가 곡선 | 세션 대화 기록 | 실측 | ✅ 판 2: 10개 세션 모두 완전 (`user01/dataset-v2.json`) |
| 3. claude.ai 채팅 | 대화 수, 길이, 구조 | 데이터 내보내기 | 추정(사용량 미기록) | 파일 필요 |
| 4. VS Code 확장, Cowork | 1·2층과 같은 항목 | 각 기기의 세션 기록 | 실측 | 파일 필요 |

## 레포트

판 2(최신): `user01/dataset-v2.json` → `user01/report-v2.html`. 판 1(노트 1편이 인용): `user01/dataset.json` → `pxt survey report research/survey/user01/dataset.json --out report.html` → `user01/report.html`. 같은 데이터셋이면 같은 레포트가 나온다. 자기 사용을 재려면 `pxt survey measure ~/.claude/projects`로 시작한다.

## 원칙
- 세션 제목과 프로젝트 이름은 공개하지 않고, 작업 종류(일반화한 범주)만 적는다.
- 진행 중인 세션은 숫자가 계속 바뀌므로, 측정 시각을 함께 적는다.
- 같은 원천을 다시 조회하면 같은 값이 나와야 한다. 바뀌는 값은 진행 중인 세션뿐이다.

## 측정 비용과 방법 선택 (2026-10-06)

세션 대화 기록을 얻는 길은 두 가지였고, 비용 차이가 컸다.

| 방법 | 어떻게 | 비용 (실측) |
|---|---|---|
| **세션 안에서 재기** | 대상 세션에 `pxt survey measure` 실행을 부탁하고 숫자만 받는다 (S01·S02·S03, S08) | 측정 요청 한 번. 다만 쉬던 세션을 다시 열면 맥락 전체를 캐시에 다시 쓴다 (S08: 287,071토큰, 모델 변경으로 241,334토큰 더) |
| **이벤트 기록 받기** | 다른 세션에서 이벤트 API를 100개씩 쪽 단위로 받아 와 잰다 (S04~S10, 그리고 S02·S03 시계열) | 연구 세션의 하위 에이전트가 이벤트 API를 약 1,250번 불렀고, 그 에이전트들의 입력이 334,527,780토큰이었다. 한 쪽에 평균 약 27만 토큰. 쪽 자체는 파일로 저장됐지만, 에이전트 하나가 수백 번 호출하는 동안 자기 맥락(호출 기록)이 길어져 매 호출이 그것을 다시 읽었기 때문이다 |

앞으로는 큰 세션을 **세션 안에서** 잰다. 이벤트 기록은 지시 원문이 필요한 경우(판정 꾸러미)와 작은 세션에만 쓰고,
받을 때는 에이전트 하나가 오래 돌지 않게 짧게 끊어(예: 20쪽마다 새 에이전트) 맥락이 길어지지 않게 한다.
자세한 내역: `self-audit-log.md`.
