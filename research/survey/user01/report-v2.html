세션은 늘 천장 근처에서 돕니다

S03의 호출 4,820번의 컨텍스트 크기입니다. 컨텍스트는 약 78만 토큰에 닿을 때만 압축되고, 다시 차오르기를 반복합니다. 잊는 시점을 정하는 것은 작업의 끝이 아니라 용량입니다.

가로축은 호출 순서, 세로축은 그 호출이 처리한 입력 토큰입니다.

지시 하나의 비용은 걸음 수 × 걸음마다 지는 짐입니다

원 하나가 세션 하나입니다. 오른쪽일수록 지시 하나에 에이전트가 많은 걸음을 밟았고, 위쪽일수록 걸음마다 무거운 컨텍스트를 들고 갔습니다. 원의 넓이는 세션의 총입력입니다.

비용은 소수의 지시에 몰립니다

지시별로 나눠 볼 수 있었던 667번을 입력이 큰 순서로 늘어놓고 누적했습니다. 상위 1%가 9.6%, 상위 10%가 42.2%, 상위 20%가 60.8%를 썼습니다. 가장 큰 지시 하나는 2.20억 토큰이었습니다.

가로축은 상위 몇 %의 지시인지, 세로축은 그 지시들이 쓴 입력의 비중입니다.

표시되는 사용량은 실제보다 작습니다

세션 목록에 표시된 값과, 호출마다 기록된 입력을 더한 값을 비교했습니다. 오래된 세션일수록 차이가 컸습니다.

에이전트는 아주 작은 걸음으로 일합니다

도구 호출의 대부분은 셸 명령입니다. 출력은 입력의 0.2%~0.4%입니다(호출마다 최종 출력이 기록된 세션 기준). 걸음 수를 줄이는 것은 짐을 줄이는 것만큼 큰 레버입니다.

가격 신호가 꺼져 있습니다

다시 읽기의 대부분은 캐시로 싸게 청구되고, 표시되는 사용량은 실제보다 작습니다. 줄일 이유가 보이지 않는 구조입니다.

측정 방법과 한계

  • 원천은 제공사가 API 호출마다 기록한 사용량(입력, 캐시 읽기, 캐시 쓰기)입니다. 추정이나 판정은 쓰지 않았습니다.
  • "지시"는 사용자가 직접 입력한 메시지입니다. 도구 결과, 시스템 알림, 압축 요약은 세지 않았습니다.
  • 이벤트 기록의 출력 토큰은 응답이 시작될 때의 값이라 쓰지 않았습니다. 출력 비율은 세션 안 기록이 있는 세션에서만 계산했습니다.
  • 표본은 한 사람입니다. 이 사람의 사용 방식을 기술할 뿐, 사람들 일반에 대한 주장이 아닙니다.
  • 컨텍스트 분해는 구조를 보여 줄 뿐, 넘어온 내용이 필요했는지는 판단하지 않습니다.
  • S01은 2026-10-05 스냅샷(호출 400번) 기준입니다.
  • S08에는 측정 요청 1턴이 더해져 있습니다.
  • S09는 세션 전체(2026-08-12 ~ 08-17)를 이벤트 기록 310쪽으로 받은 완전 측정입니다 (판 2).
  • S02, S03의 호출별 시계열과 지시별 목록은 이벤트 기록을 스냅샷 호출 수에서 잘라 얻었습니다. 사용량은 세션 안 기록과 같습니다. 이벤트 기록은 지시를 조금 더 잘게 나눠서(S02 49개, S03 299개) 지시 수는 세션 안 기록 값(48개, 275개)을 그대로 둡니다 (판 2).
  • S01에는 스냅샷 전까지의 하위 에이전트 호출이 들어 있습니다 (판 2).
