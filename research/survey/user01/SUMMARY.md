# user01 현상조사 1차 정리 (2026-10-06)

대상: 한 사용자(프로젝트 대표)의 Claude Code 클라우드 세션 전체. 2026-07-10 ~ 10-05, 세션 12개 중 토큰 기록이 있는 10개를 측정했다. 원천은 제공사가 호출마다 기록한 사용량이다. 해석은 하지 않고 현상만 기술한다. 표본은 한 사람이다.

## 1. 규모

| 항목 | 값 |
|---|---|
| 처리한 입력 | **58.8억 토큰 이상** (S09는 부분 측정이라 하한) |
| API 호출 | 약 14,900번 |
| 사용자 지시 | 591번 |
| 지시 1건당 입력 | 평균 **약 1,000만 토큰** |
| 입력 중 캐시 읽기 | 약 99% |
| 출력 | 세션 목록 기준 1,014만 이상 (전체 토큰의 약 0.2%) |
| 실제 작업 시간 | 약 150시간 → 시간당 약 4,000만 토큰 |

세션 목록에 표시된 사용량(39.5억)은 실제보다 작다. 특히 8월 세션 6개는 모두 실제의 25~50%만 담고 있었다.

며칠씩 이어진 세션 5개가 사용량의 93%다.

## 3. 반복되는 현상

1. **컨텍스트 천장이 약 78만 토큰이다.** 큰 세션 7개가 모두 이 근처에서 압축됐다. 압축 뒤에는 6~14만으로 떨어지고 다시 차오르는 톱니 모양이 반복된다. 그래서 대부분의 호출이 30만~60만 토큰을 들고 간다.
2. **지시 한 번의 비용이 크고, 편차가 매우 크다.** 세션별 지시당 입력의 중앙값은 300만~860만이다. 최대는 S05에서 **2.2억**(호출 560번)이었고, 그 밖에도 8,720만, 7,585만, 6,378만이 있었다. 몇 개의 "폭주 지시"가 큰 몫을 차지할 가능성이 있다.
3. **도구 호출의 대부분은 명령 실행(Bash)이다.** 10개 중 9개 세션에서 56~90%였다.
4. **폰에서 시작한 세션이 대부분이다**(12개 중 11개). 세션 하나를 며칠씩 이어 쓴다.
5. **재개와 모델 변경은 캐시를 처음부터 다시 쓴다.** 보관된 세션에 메시지 하나를 보내자 컨텍스트 전체(28.7만)를 캐시에 다시 썼다. 모델을 바꾸자 또 24만을 다시 썼다.

## 4. 다음에 볼 질문 (목표 수립 전)

- **지시 단위 쏠림:** 상위 몇 %의 지시가 입력의 몇 %를 쓰는가? 측정 스크립트에 지시별 입력 목록(숫자만)을 추가하면 볼 수 있다.
- **폭주 지시의 성격:** 호출 수백 번짜리 지시는 어떤 작업에서 생기는가? 자동 반복, 실패 재시도, 긴 빌드나 테스트 루프 중 무엇인가?
- **천장 근처의 비용:** 입력 중 몇 %가 압축 직전(60만 이상) 구간에서 쓰이는가?
- **이미지:** S03에만 436장이 있다. 이미지가 컨텍스트에서 차지하는 몫은 얼마인가?
- **다른 사용처:** claude.ai 채팅, VS Code 확장, Cowork 기록. 대표가 나중에 제공한다.

## 측정 방법과 비용

- **세션 안 기록:** S01, S02, S03. 대표가 해당 세션에 직접 요청해서 `measure_session.py`를 실행했다.
- **이벤트 기록:** 나머지 세션은 `parse_events.py`로 받았다. 이벤트 기록의 출력 토큰은 응답 시작 시점 값이라 쓰지 않았다.
- **S09는 부분 측정이다.** 8월 15일 이후 분량인 150쪽만 받았다. 앞 구간은 기록이 빽빽해서 받는 비용이 너무 커 멈췄다.
- **측정 비용:** 이벤트 기록을 받는 데 하위 에이전트 호출 수천 번이 들었다. 큰 세션은 그 세션 안에서 직접 재는 것이 가장 싸다.
