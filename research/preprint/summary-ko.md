# 한글 요약: 잊지 말고 내려놓았다가 다시 불러라 (초안)

> 영문 프리프린트 *Paging, Not Forgetting: An Offline-Optimal Bound on Context Residency in LLM Agents*의 요약이다. 세부 내용은 [outline.md](outline.md), [../framework.md](../framework.md), [../belady-bound.md](../belady-bound.md)에 있다.

## 무엇을 물었나
AI 에이전트는 호출할 때마다 컨텍스트 전체를 다시 읽는다. 그래서 처리하는 입력량이 세션 길이의 제곱으로 늘어난다. 우리는 이렇게 물었다. **그 세션에 꼭 필요했던 컨텍스트는 최소 얼마였나?**

## 단위부터 바꿨다
- 토큰은 청구서의 단위일 뿐 물리적 비용의 단위가 아니다. 효율로 토큰 단가만 내리면 사용량이 늘어나 상쇄된다(제번스 역설).
- **기본 단위:** 가치 있는 결과 1건당 연산(토큰·FLOPs)
- **확장 단위:** 가치 있는 결과 1건당 **메모리 상주량**(KV 캐시 바이트·초). 반도체 수요, 그중에서도 HBM 수요와 직접 연결되는 단위다.
- 프롬프트 캐싱은 연산을 줄이는 대신 KV 상태를 메모리에 붙잡아 둔다. 다시 읽기가 싸진다고 긴 컨텍스트가 공짜가 되는 것이 아니라, 비용이 연산에서 메모리 용량으로 옮겨 갈 뿐이다.

## 방법
1. 컨텍스트를 세그먼트로 나눈다: 사용자 프롬프트, 답변, 도구 입력, 도구 결과 등. 세그먼트마다 언제 들어와서 언제 나가는지 기록한다.
2. 나중의 출력이 그 세그먼트의 고유 토큰을 재사용하면 그 호출에서 "사용됐다"고 본다.
3. **미래를 아는 오라클**이 남겼을 최소 상주량을 계산한다. 다시 불러오는 비용 *P*를 0부터 무한대까지 바꿔 가며 계산한다.
4. 사용 사이의 간격마다 "계속 들고 있기"와 "내려놓았다 다시 부르기" 중 싼 쪽을 고르면 그것이 정확한 최적이다(증명 포함). 벨레이디의 최적 교체 알고리즘(1966)과 같은 원리, 즉 다음 사용 시점을 아는 것에서 출발한다.
5. 세그먼트 크기는 제공사가 보고한 실측 사용량에 맞춰 보정한다. 그래서 모델이 매 호출의 실측 입력과 정확히 일치한다.

## 결과 (세션 1개, 호출 322회, 입력 1억 4,927만 토큰)
| 정책 | 줄일 수 있는 입력 |
|---|---:|
| 마지막 사용 뒤에만 버린다(다시 불러오기 없음) | **9.1%** |
| 오라클, 다시 부르는 비용 1,000토큰 | 47.5% |
| 오라클, 다시 부르는 비용 0 | **50.1%** |

- **잊는 것보다 내려놓았다 다시 부르는 것이 훨씬 크다.** 대부분의 컨텍스트는 나중에 다시 쓰이지만 그 사이의 모든 호출에서 필요한 것은 아니다. 에이전트는 내용(payload) 대신 **포인터**(경로·버전·범위)를 들고 있다가 필요할 때 불러와야 한다.
- 컨텍스트에 상주한 것 중 가장 큰 항목은 **에이전트가 스스로 디스크에 쓴 내용**(25.1%)이었다. 그중 83.5%는 필요 없는 상주였다. 원본은 이미 디스크에 있다.
- **입력의 3분의 1(32.4%)은 기록에서 보이지 않는다.** 사용자도 감사 도구도 볼 수 없으니, 제공사가 공개해야 한다.
- 탐지 기준을 바꾼 민감도 분석 18가지 조합 모두에서 결론(다시 부르기 ≫ 잊기)이 유지된다.

## 한계
표본이 세션 1개다. 사용 탐지가 어휘 기반이라 양쪽 방향으로 틀릴 수 있다. 오라클은 미래를 안다. 그래서 이 수치는 기회의 크기이지 구현 가능한 정책의 성과가 아니다. 논문 제출 전에 여러 세션과 여러 에이전트의 기여 데이터를 모은다. 누구나 `pxt agent bound`로 자기 세션을 측정할 수 있다.
