# 연산 버블 지수 (Compute Bubble Index, CBI) — 설계 v0.1

> **투자된 연산 중 실제로 가치를 만든 연산은 얼마인가?**
> 위(자본)에서 내려오는 숫자와 아래(실측)에서 올라오는 숫자를 처음으로 한 장에 놓는다.

## 1. 원칙

- **격차는 단정하고, 버블은 메시지로.** 지수가 말하는 것은 측정된 격차다. "버블"이라는 단어는 캠페인 언어로 쓴다.
- **1차 출처만.** 모든 수치에 출처(공시, 실적 발표, 논문, 자체 실측), 날짜, 버전을 붙인다. 언론 기사는 1차 출처를 찾는 단서로만 쓴다.
- **측정값과 추정치를 분리한다.** 모든 수치에 `measured`, `reported`, `estimated` 중 하나를 붙이고, 추정치에는 구간을 함께 표시한다.
- **재현 가능해야 한다.** 데이터, 코드, 계산식을 공개하고, 누구나 같은 숫자를 다시 계산할 수 있게 한다. 방법론은 버전을 관리하고, 정정 이력은 전부 공개한다.
- **반론 채널을 연다.** 모델사나 기업이 데이터로 반박하면 검토해서 반영하고, 그 과정도 공개한다. 이것이 투트랙 원칙의 "거울" 역할이다.

## 2. 구조: 세 개의 격차

```
           배치된 연산 (Deployed compute)
                   │
   ① 가동 격차  ── 실제로 돌아가는가?               U = 가동률
                   │
   ② 모델 격차  ── 필요한 만큼만 계산하는가?         M = 과잉 계산 비율
                   │
   ③ 사용 격차  ── 그 계산이 필요한 요청이었는가?    W = 회피 가능 사용 비율
                   │
           가치를 만든 연산 (Effective compute)

   유효 연산 비율  E = U × (1 − M) × (1 − W)
```

그리고 이 흐름 바깥에서 돈의 흐름을 따로 본다.

```
   ④ 자본 격차 ── AI 설비투자 대비 AI 매출, 순환 투자 비중, 감가상각 가정
```

**헤드라인 지수 두 개**
- **유효 연산 비율 E**: "배치된 AI 연산 중 가치를 만든 것은 E%"
- **자본 격차 비율 K**: "AI 인프라에 들어간 1달러당 AI 매출은 K달러"

단위가 다른 두 숫자를 하나로 합치지 않는다. 연산(토큰, FLOP)과 돈(달러)을 억지로 합치면 반박당하기 쉽기 때문이다.

## 3. 하위 지표

### ① 가동 격차 (U)

| 지표 | 정의 | 출처 유형 |
|---|---|---|
| 클러스터 가동률 | 배치된 가속기 중 실제로 작업을 처리한 시간의 비율 | 공개 추정, 클라우드 가격·가용성 신호 |
| MFU (Model FLOPs Utilization) | 이론 최대 FLOP 대비 실제 유효 FLOP | 논문, 기술 보고서 |
| 유휴·대기 용량 | 확보했지만 쓰지 않는 용량(예약 후 미사용) | 공시, 업계 보고 |

### ② 모델 격차 (M): 자체 공개 벤치마크로 측정

| 지표 | 정의 |
|---|---|
| **과잉 추론 비율** | 추론(reasoning) 없이도 정답인 과제에 쓰인 추론 토큰의 비율 |
| **과잉 모델 비율** | 같은 품질 기준을 만족하는 가장 작은 모델 대비, 실제 사용 모델의 추가 연산 |
| **장황함 지수** | 정답을 유지하는 최소 응답 길이 대비 실제 응답 길이 |

벤치마크 설계 요건: 과제를 난이도별로 층화하고, 품질 기준을 사전에 고정하고, 모델·버전·설정과 실행 비용을 모두 공개한다.

### ③ 사용 격차 (W): 크라우드 실측

| 지표 | 정의 | 출처 |
|---|---|---|
| 회피 가능 연산 비율 | 낭비 없이 같은 결과를 얻었을 때와 비교한 초과분 (현재 `savings_pct`) | 기여된 대화 골격 |
| 실측 절감률 | 프록시와 플러그인의 절감 전후 실측값 | 로컬 프록시 텔레메트리 (동의분) |
| 에이전트 낭비율 | 코딩 에이전트의 반복 시도와 불필요한 컨텍스트 비중 | 에이전트 플러그인 |

### ④ 자본 격차 (K)

| 지표 | 정의 | 출처 |
|---|---|---|
| 설비투자 대비 AI 매출 | AI 관련 설비투자 대비 확인 가능한 AI 매출 | 기업 공시, 실적 발표 |
| 순환 거래 비중 | 칩 공급사·클라우드가 투자한 AI 기업이 다시 그 공급사의 칩과 클라우드를 구매하는 구조의 금액 비중 | 공시, 계약 공개 자료 |
| 감가상각 격차 | 회계상 내용연수 가정과 칩 세대 교체 주기·임대 가격 하락 속도의 차이 | 공시(회계 정책), 시장 가격 |
| 전력 확보 대비 실가동 | 계약·발표된 데이터센터 전력 용량 대비 실제 가동 용량 | 공시, 전력 당국 자료 |

## 4. 데이터 파이프라인

```
 공시·실적·논문 ──► 큐레이션된 데이터셋 (CSV + 출처 URL + 날짜 + 등급)  ─┐
 자체 벤치마크 실행 ─► 결과 + 실행 로그 + 비용                             ├─► 계산 엔진 ─► 대시보드 / 분기 리포트
 골격 기여·프록시 실측 ─► 집계 (k-익명, 동의분)                            ─┘        (버전 관리)
```

- 자본·가동 데이터는 사람이 큐레이션하고 2인이 교차 검증한다. 변경할 때마다 PR로 리뷰한다.
- 계산 엔진은 오픈소스로 공개하고, 모든 수치에 신뢰 구간을 계산해 붙인다.

## 5. 출시 계획

| 단계 | 산출물 |
|---|---|
| **1단계 (병행)** | CBI v0. ④ 자본 격차 대시보드(공개 자료 기반)와 ② 과잉 추론 벤치마크 프로토타입. ③은 현재 골격 데이터로 시작한다 |
| **2단계** | CBI v1. 첫 분기 리포트 "골드러시 계산서"를 발간하고, 프록시 실측을 ③에 합류시킨다. 반론 채널을 연다 |
| **3단계** | CBI를 업계 참조 지표로 정착시킨다. TEI(토큰 효율 지수)와 연동하고, 모델사와 기업이 자기 데이터를 검증받아 제출할 수 있는 제출 프로토콜을 만든다 |
