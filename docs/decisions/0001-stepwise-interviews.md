# ADR-0001: 단계별 인터뷰 진행, 되돌리기 어려운 결정 먼저

- 날짜: 2026-10-05
- 상태: 승인
- English summary: every step runs as interview → design approval → build → report. Irreversible decisions (naming) go before reversible ones (code), and launch goes last.

## 배경
프로젝트 헌장(v0.2)으로 큰 틀은 정해졌다. 이제 실행 단계에서 방향이 어긋나지 않도록 결정 절차가 필요하다.

## 결정
1. 각 단계는 ① 인터뷰로 방향 결정 ② 설계 요약(범위, 범위 밖, 완료 기준) 승인 ③ 구현과 검증 ④ 결과 보고 순서로 진행한다.
2. 단계마다 결정 기록(ADR)을 `docs/decisions/`에 남긴다. 헌장은 큰 틀만 유지한다.
3. 순서는 되돌리기 어려운 정도로 정한다.
   - **제품명·브랜드**를 가장 먼저 정한다. 패키지, 조직, 도메인, CLI, 상표는 사용자가 생기면 굳어진다.
   - **제품 개발**(코딩 에이전트 플러그인, 브라우저 측 추출)이 그다음이다. 코드는 되돌릴 수 있다.
   - **런칭**은 마지막이다. 첫인상은 한 번뿐이므로 보여 줄 제품이 준비된 뒤에 한다.

## 결과
- 구현은 승인된 범위 안에서만 한다. 범위 밖의 발견은 다음 인터뷰 안건으로 넘긴다.
