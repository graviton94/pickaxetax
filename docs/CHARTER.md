# 프로젝트 헌장 (Project Charter) v0.2

> 2026-10 프로젝트 스타트 디스커션 결과 (v0.2: 연산 버블 비판으로 범위 확장). 이후 모든 설계·제품·조직 결정은 이 문서를 기준으로 하며, 바꿀 때는 이 문서부터 고친다.

## 1. 문제: 골드러시의 계산서

지금 AI 산업의 성장은 **더 많은 GPU, 더 큰 데이터센터, 더 많은 전력**이라는 한 방향으로만 흐른다. 이 구조에서 확실히 돈을 버는 것은 곡괭이를 파는 쪽(반도체, 데이터센터 공급망)이다. 정작 AI를 만들고 쓰는 쪽은 늘어나는 연산 비용을 떠안는다. 수요가 실제 가치보다 부풀려져 있다면 이 흐름은 과잉투자와 그 뒤의 붕괴, 즉 골드러시 파산으로 끝난다.

부풀려진 수요의 상당 부분은 **낭비**다.
- 채팅형 모델은 매 턴 대화 전체를 다시 읽는다. 비용이 대화 길이의 제곱으로 커진다.
- 늦게 붙인 조건, 재질문, 끝난 뒤의 인사, 한 창에서의 주제 전환, 불필요한 대용량 컨텍스트
- 코딩 에이전트의 반복 시도와 불필요한 파일 읽기
- 이미 수많은 사람이 풀어 본 질문을 매번 처음부터 다시 생성하는 것

낭비는 대화에서 끝나지 않는다. **AI 연산 전체가 버블의 구조를 갖고 있다.**
- **인프라·자본 층**: 설비투자가 실제 AI 매출보다 앞서 달린다. 칩 공급사가 고객에게 투자하고, 그 돈으로 다시 자기 칩을 사게 하는 순환 구조가 있다. 감가상각 가정은 실제 칩 교체 주기를 반영하지 못한다.
- **모델 층**: 쉬운 일에 큰 모델을 쓰고, 생각할 필요가 없는 문제에 긴 추론 토큰을 쓴다.
- **사용 층**: 대화와 에이전트에서 재독, 재시도, 불필요한 컨텍스트가 반복된다.

**우리의 명제: 새로 짓기 전에, 이미 가진 연산부터 제대로 쓰자.**

## 2. 미션 · 비전 · 북극성

- **미션**: 투자된 AI 연산과 가치를 만든 AI 연산 사이의 격차를 측정해 공개하고, 전 세계 사용자의 대화 *구조*를 모은 공유 두뇌로 그 격차를 줄인다.
- **비전**: AI의 발전 지표가 "얼마나 많이 계산했는가"에서 "얼마나 적게 계산하고 해결했는가"로 바뀐 세상
- **북극성 지표**: **검증된 회피 연산량**. 우리 도구와 데이터 덕분에 실제로 계산하지 않아도 된 토큰, 연산, 전력

## 3. 하나의 정체성, 네 개의 얼굴

네 가지는 따로 노는 사업이 아니라 하나의 순환 구조다.

| 얼굴 | 역할 | 형태 |
|---|---|---|
| **공유 두뇌** | 핵심 자산 | 해결 경로 그래프 + 효율 학습 데이터셋 |
| **교정 도구** | 사용자 접점 | 프롬프트 컴파일러 (로컬 프록시·SDK, 코딩 에이전트 플러그인) |
| **측정·고발** | 증거 | **연산 버블 지수(CBI)**, 분기 리포트 "골드러시 계산서" ([설계](BUBBLE_INDEX.md)) |
| **효율 표준** | 인정받는 수단 | 토큰 효율 지수(TEI), 벤치마크와 인증 |

### 플라이휠: 공유가 모두의 개선이 되는 구조

```
 ① 사용자가 로컬에서 도구 사용 ──► ② 절감 전·후 실측 (원문은 기기 밖으로 나가지 않음)
          ▲                                    │
          │                                    ▼
 ⑥ 더 똑똑해진 컴파일러·경로 추천     ③ 골격(+선택 시 해결 카드) 기여
          ▲                                    │
          │                                    ▼
 ⑤ 모델사 압박·협력 → UX·모델 개선 ◄── ④ 공유 두뇌 갱신 + 공개 지표
```

- 기여할수록 내 도구가 좋아진다 (⑥). 이것이 기여를 이어가게 하는 직접적인 보상이다.
- 기여할수록 업계 전체의 증거가 쌓인다 (④→⑤). 이것이 공익적 보상이다.
- 모델사는 이 데이터를 무시하기 어렵다. 공개된 지표이고, 그대로 학습과 평가에 쓸 수 있는 형태이기 때문이다.

## 4. 핵심 원칙

1. **로컬 우선.** 원문은 사용자 기기(브라우저, CLI, 프록시)에서만 처리한다. 서버로 가는 것은 골격뿐이다.
2. **2단계 동의.** 기본으로 기여되는 것은 골격(구조, 수치, 주제 라벨)이다. 해결 카드(질문 요지와 최종 답 요지, 비식별화)는 별도로 명시적 동의를 받은 경우에만 기여된다. 모든 기여는 철회할 수 있다.
3. **토큰을 아끼는 도구는 토큰을 쓰지 않는다.** 핵심 분석과 컴파일 경로에서는 LLM을 호출하지 않거나 최소한으로만 쓴다. 우리 자신의 연산 사용량도 공개한다.
4. **냉정한 데이터, 도발적 메시지.** 숫자와 방법론은 학술 수준으로 검증할 수 있어야 한다. 측정값과 가정치는 언제나 구분해서 표시한다. 메시지는 강하게 하되 숫자를 과장하지 않는다.
5. **적이 아니라 거울.** 투트랙으로 간다. 공개 지표로 압박하고, 동시에 데이터셋과 표준을 함께 쓸 협력 창구를 연다.
6. **공공재는 사유화되지 않는다.** 데이터, 표준, 핵심 엔진은 재단이 철회할 수 없는 오픈 라이선스로 보유한다.

### 우리가 할 수 있는 것과 없는 것

반도체 과잉생산을 우리가 직접 막을 수는 없다. 우리가 바꿀 수 있는 것은 **증거**다. 애널리스트들은 위에서 아래로 설비투자 숫자를 추적한다. 하지만 그 연산이 실제로 어디에 얼마나 쓰이고 그중 얼마가 낭비인지는 아무도 측정하지 못한다. 우리는 아래에서 위로 실측한 데이터(모델 층, 사용 층)와 공개 자본 데이터를 한 장에 놓는다. "배치된 AI 연산 중 가치를 만든 것은 E%"라는 숫자가 공개 데이터로 입증되면 무한 증설의 논리가 약해진다. 투자자, 정책 당국, 기업 구매자가 효율을 요구하게 된다. 우리의 레버는 증거와 도구다.

### 연산 버블 지수 (CBI)

```
 유효 연산 비율  E = U(가동률) × (1 − M: 모델 과잉 계산) × (1 − W: 회피 가능 사용)
 자본 격차 비율  K = 확인 가능한 AI 매출 / AI 설비투자
```

- 격차는 데이터로 단정하고, "버블"은 메시지로 쓴다. 모든 수치에 1차 출처, 측정·보고·추정 등급, 신뢰 구간을 붙인다.
- 에너지(Wh, CO₂)는 별도의 측정 층이 아니라, 낭비된 연산을 표현하는 환산 단위로 쓴다.
- 상세 설계: [BUBBLE_INDEX.md](BUBBLE_INDEX.md)

## 5. 공유 두뇌의 세 부품

| 부품 | 무엇인가 | 입력 |
|---|---|---|
| **해결 경로 그래프** | 같은 아젠다를 최소 턴으로 해결한 구조 패턴. 새 질문이 오면 검증된 경로(질문 순서, 필요한 조건, 출력 형식)를 먼저 제시한다 | 골격 (기본) |
| **프롬프트 컴파일러** | 장황하고 반복적이고 조건이 흩어진 요청을 최소 토큰의 정밀한 요청으로 바꾼다. 이력 압축, 주제 분리, 중복 요청 캐시를 포함한다 | 로컬 원문 + 공유 두뇌의 경로 |
| **효율 학습 데이터셋** | 더 짧고 정확한 응답, 되묻기 최적화, 장황함 억제를 학습하고 평가하는 공개 데이터셋 | 골격 + 해결 카드 (동의분만) |

## 6. 제품과 로드맵

브랜드는 둘로 나눈다. 마스터 브랜드는 **Pickaxe Tax**(곡괭이세)이고, 제품명은 Pickaxe Tax Proxy와 Pickaxe Tax Bench처럼 설명형으로 붙이며, 지수는 Compute Bubble Index다. 운동명 **#AntiTokenMaxing**은 해시태그와 캠페인 이름으로 쓴다. ([ADR-0002](decisions/0002-brand-pickaxe-tax.md))

| 단계 | 기간(목표) | 산출물 |
|---|---|---|
| **0. 기반** (완료) | — | 골격 추출기, 토큰 회계, 그래프 저장소, 웹 분석기 MVP |
| **1단계 진행 상황** | 진행 중 | ✅ 로컬 프록시 v0 (실측 ledger, 감사 메시지 로컬 응답, 이력 압축, 로컬 캐시) · ✅ 과잉 추론 벤치마크 하네스 v0 (크라우드 실행, 중복 측정 차단) · ✅ CBI 데이터 스키마와 검증기 (2인 검증 규칙) · ✅ 로컬 우선 정적 웹 (브라우저 엔진, 북마클릿 링크 입력, CSP로 전송 차단, [ADR-0003](decisions/0003-local-first-static-web.md)) · ✅ 코딩 에이전트 감사 도구와 가드 훅 (Claude Code 플러그인, [ADR-0005](decisions/0005-coding-agent-audit-and-guard.md)) · ✅ 2단 기여 경로 (익명 원클릭 + GitHub 검증, [ADR-0006](decisions/0006-contribution-paths.md)) |
| **1. 엔진 + 플래그십 + CBI v0** | ~3개월 | 코어 엔진 분리 (언어 중립 스펙과 참조 구현) · **로컬 프록시+SDK** (OpenAI/Anthropic/Gemini 호환 엔드포인트, 실측 로그) · **코딩 에이전트 플러그인** (컨텍스트 낭비 감사) · 웹 분석기의 클라이언트 측 추출 전환 · **병행: CBI v0** (자본 격차 대시보드, 과잉 추론 벤치마크 프로토타입) |
| **2. 공유 두뇌 v1 + CBI v1** | ~6개월 | 골격 기여 프로토콜 · 해결 경로 그래프와 추천 · 개인·팀·국가별 절감 대시보드 · 첫 분기 리포트 "골드러시 계산서" · 프록시 실측의 CBI 합류 · 반론 채널 |
| **3. 표준·데이터셋** | ~12개월 | CBI·TEI를 업계 참조 지표로 정착 · 효율 학습 데이터셋 v1 (ODbL) · 모델사 협력 창구와 데이터 제출 프로토콜 · 기업 절감 서비스 베타 |

**1단계의 기술적 귀결**: 로컬 우선 원칙에 맞추려면 현재 웹 분석기가 서버에서 원문을 받는 구조를 바꿔야 한다. 추출을 브라우저(WASM 또는 JS 포팅)와 CLI·프록시로 옮기고, 서버는 골격만 받도록 API를 분리한다.

## 7. 조직과 거버넌스

```
 ┌──────────── 재단 (비영리) ─────────────┐        ┌──── 공익 벤처 (PBC) ────┐
 │ 공유 두뇌 데이터 · 효율 표준(TEI)        │ 라이선스 │ 기업 절감 서비스          │
 │ 핵심 엔진 · 공개 리포트 · 거버넌스        │ ───────► │ 효율 인증·벤치마크 컨설팅 │
 │ 재원: 후원 · 그랜트                     │          │ 투자 유치 · 인수 가능     │
 └────────────────────────────────────────┘        └─────────────────────────┘
```

- 벤처는 인수될 수 있다. 하지만 **재단이 가진 공공재는 인수 대상이 아니다.** 사용자가 맡긴 데이터에 대한 신뢰와 워치독 기능은 어떤 출구 시나리오에서도 유지된다.
- 출구 전략: 관심과 채택을 빠르게 확보한 뒤 ① 전략적 인수(벤처) 또는 ② 독립적인 효율 표준 기관으로 성장(재단)
- 수익원: 기업 절감 서비스(성과 기반), 효율 인증·벤치마크, 후원·그랜트

## 8. 운영 원칙: 최소 비용, 기여 기반

비용은 최소화하고, 오픈소스와 글로벌 사용자의 기여로 운영한다. 낭비를 비판하는 조직이 낭비하면 안 된다.

| 영역 | 방식 | 프로젝트 비용 |
|---|---|---|
| 프록시·플러그인 | 사용자 PC에서 실행 | 0 |
| 벤치마크 (CBI M층) | 기여자가 로컬 오픈 모델이나 본인 키로 실행하고 결과 JSON을 PR로 제출. 같은 측정은 한 번만 하며, 중복 실행은 러너가 거부 | 0 |
| CBI 자본 데이터 | git이 DB. 출처를 단 CSV를 PR로 기여하고, CI가 형식과 2인 검증 규칙을 확인 | 0 |
| 사용 데이터 (CBI W층) | 프록시 ledger의 익명 집계를 자발적으로 제출 | 0 |
| 웹·대시보드 | 정적 호스팅 우선, 분석은 클라이언트 측 | 무료 티어 |
| CI | 공개 저장소 무료 CI | 0 |

- 유료 인프라는 필요가 증명된 경우에만 도입하고, 그 비용을 공개한다.
- 우리 자신의 연산 사용량도 공개 지표에 포함한다.

## 9. 시장 진입

- **첫 사용자**: 개발자와 파워유저. 토큰 비용을 직접 체감하고 오픈소스로 확산할 수 있는 층이다.
- **런칭 순서**: 영어를 우선으로 글로벌에 출시하고(GitHub, Hacker News, Reddit 등) 한국어를 동시에 지원한다. 이후 커뮤니티 번역으로 확장한다.
- **참여 동기**: ① 내가 줄인 양의 가시화(개인·팀·국가 대시보드, 기여 크레딧) ② 기여할수록 똑똑해지는 도구
